# vnf-stroll

Exact solvers and reproducible experiments for placing and migrating a chain of virtual network
functions (VNFs) in fat-tree data centers. The problems are those of

> V. Tran, J. Sun, B. Tang and D. Pan, "Traffic-Optimal Virtual Network Function Placement and
> Migration in Dynamic Cloud Data Centers," IEEE IPDPS 2022, pp. 919–929,
> doi:10.1109/IPDPS53621.2022.00094.

The exact optima serve as ground truth for evaluating heuristics and learned solvers.

## Problems

VM pairs (s_i, t_i) communicate at rates λ_i, with Λ = Σ λ_i. Their traffic must traverse the service
function chain f_1 → … → f_n, and the n VNFs go on **n distinct switches** p_1, …, p_n. c(u, v) is
the shortest-path cost between two nodes (hops when links are unweighted).

| Problem | Objective |
|---|---|
| TOP-1 | one VM pair: λ · [c(s, p_1) + Σ_j c(p_j, p_{j+1}) + c(p_n, t)], equivalent to the n-stroll problem |
| TOP (Eq. 1) | l VM pairs share the chain: A(p_1) + B(p_n) + Λ · Σ_j c(p_j, p_{j+1}), with A(v) = Σ_i λ_i c(s_i, v) and B(v) = Σ_i λ_i c(v, t_i) |
| TOM (Eq. 8) | the chain sits at p and traffic changes: choose m minimizing μ · Σ_j c(p_j, m_j) + (Eq. 1 cost of m under the new rates) |

`n` always counts VNFs, i.e. distinct switches, not counting the two hosts.

## Layout

```
vnfstroll/
  graph.py           undirected weighted graph, shortest paths
  fattree.py         k-ary fat-tree; hosts numbered h1, h2, ... as in the paper; uniform link delays
  workload.py        VM pairs and rates as in the paper's experiments; diurnal model (Eq. 9)
  instance.py        Eq. 1 / Eq. 8 on the metric closure of the network
  checker.py         independent cost checker (own Dijkstra on the raw link list)
  exact/
    search.py        exact n-stroll search on unweighted graphs (iterative deepening, exhaustive DFS)
    milp.py          MILP for TOP-1, TOP and TOM on any weighted graph (HiGHS through SciPy)
    decomposition.py exact TOP on unweighted fat-trees: best ingress/egress pair plus an exact inner stroll
    closed_form.py   closed forms: TOP-1 lower bound, TOP with traffic spread over the pods
    brute_force.py   enumeration of all placements, for tests
experiments/         one script per result (R1, R2)
results/             outputs of the scripts (Markdown reports, CSV, figures)
data/                values read from the paper's Fig. 9, for comparison
tests/               unit tests, including the paper's worked examples and Theorem 4
```

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest
```

The tests take about ten seconds. They cover the fat-tree's structure, the paper's Example 1
(migration on a k = 2 fat-tree: 410 → 1004 → 416), Example 2 (optimal 2-stroll of Fig. 4(a) = 6),
Example 3 (seven VNFs from h4 to h5 on a k = 4 fat-tree = 8 hops), Theorem 4 (TOM with μ = 0 equals
TOP), and agreement between the search, the MILP, the decomposition, brute force and the checker.

## Results

Each result is regenerated by one command, run from the repository root. Every reported optimum is
re-costed by the independent checker, and the reports list the command, code version and machine.

| | Command | Time (Apple M1) | Report |
|---|---|---|---|
| R1 | `.venv/bin/python -m experiments.r1_top1` | 1.5 min | [results/r1_top1.md](results/r1_top1.md) |
| R2 | `.venv/bin/python -m experiments.r2_top_fig9` | 6 min | [results/r2_top.md](results/r2_top.md) |

Most of the R2 time goes to MILP cross-checks; the exact solvers themselves take milliseconds.

**R1, TOP-1.** Exact optimum for every ordered pair of distinct hosts of k = 4, 6 and 8 fat-trees
(16,256 pairs at k = 8) and for one pair of each type up to k = 16, n = 1..13. The optimum depends
only on n and on whether the hosts share a rack, a pod or neither; for k ≥ 8 it equals a simple
counting and parity lower bound (`top1_lower_bound`). An exact solve takes about 0.03 ms.

**R2, TOP.** At the settings of the paper's Fig. 9 (k = 8, l = 500–2000 VM pairs, n = 3–11, the
paper's workload, 20 workloads per setting), the exact optimum is Λ·(n + 5) for every odd n and every
workload: the chain starts and ends at core switches, which are exactly 3 hops from every host. For
even n it is Λ·(n + 6 − 2·f_max), with f_max the busiest pod's share of the traffic. Relative to n = 3
the exact costs are (n + 5)/8, and the paper's plotted Optimal follows these ratios to within 0.2%
(`results/r2_fig9.png`). The decomposition solves each instance in about a millisecond, and the MILP
confirms every one of them.

## Assumptions

Where the paper leaves a detail open, the code makes the following choices:

- Rates are uniform within each of the paper's bands (25% in [0, 3000), 70% in [3000, 7000],
  5% in (7000, 10000]).
- 80% of VM pairs sit on two different hosts under the same edge switch; the other 20% have a
  uniformly random destination host different from the source.
- The diurnal model multiplies a flow's rate by 1 + τ_h (Eq. 9, as plotted in Fig. 8), with the
  east-coast day starting at 6 AM and the west-coast day at 9 AM.
- Weighted fat-trees draw link delays uniformly with mean 1.5 and variance 0.5, i.e. U[0.275, 2.725].
